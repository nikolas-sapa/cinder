Session state machine

Every cinder session is a small automaton: an invite link, three noise_xx flights, a sealed transport, a trust flag. Below is the full graph, hand-set in box-drawing characters. The marker steps the happy path; denied is absorbing.

Session state machine. States: invite, handshake, sealed, verified, unverified, wiped, denied. Transitions: invite to handshake via cinder link; handshake to sealed after three noise_xx flights; sealed loops on rekey; sealed to verified on sas match; sealed to unverified on key change, which blocks sends; unverified back to verified on sas match; verified to wiped via chat.wipe; any state to denied via contact.deny. Denied is terminal; there is no un-deny.

states
  • INVITElink issued, no keys yet
  • HANDSHAKEnoise_xx in flight
  • SEALEDtransport live, trust off
  • VERIFIEDsas matched, trusted
  • UNVERIFIEDkey changed, sends blocked
  • WIPEDhistory destroyed, keys kept
  • DENIEDabsorbing, no un-deny
edges
  • INVITE ──▶ HANDSHAKEcinder:// link
  • HANDSHAKE ══▶ SEALEDnoise_xx · 3 flights
  • SEALED ──▶ VERIFIED/sas match
  • SEALED ◀─┐ SEALEDrekey (loop)
  • SEALED ──▶ UNVERIFIEDkey change · sends blocked
  • UNVERIFIED ──▶ VERIFIEDsas match
  • VERIFIED ──▶ WIPEDchat.wipe
  • any ──▶ DENIEDcontact.deny · terminal
